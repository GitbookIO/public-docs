# Create a change request

Within a section, click **Edit** in the [section header](../../../resources/the-gitbook-interface.md) to start a new change request. Edit or delete content as needed — changes save automatically, and others can join to collaborate in real time.

Add a title and description to give reviewers context. You can also link the change request to a source:

* Linear issues
* GitHub pull requests or issues
* Jira tickets
* General URLs

These links appear on the change request, so reviewers can trace the work back to its origin.

Once you're happy with your changes, use the header bar to [request a review](review-and-merge.md#request-a-review) or [merge directly](review-and-merge.md#merging-a-change-request) into the main branch.

### Creating a change request with GitBook Agent

GitBook Agent is an AI teammate that can plan and implement change requests from any instructions you give it — see Build with AI → [Write and edit with Agent](../../gitbook-ai/agent/write-and-edit.md).

Click the GitBook Agent icon next to **Edit** and ask it to implement changes. Some things you can ask it to do:

* Add usage examples
* Improve page SEO
* Enhance clarity
* Check for consistency
* Fix typos and spelling errors
* Link related content

### Previewing a change request

Click **Preview** in the [section header](../../../resources/the-gitbook-interface.md) to see your change request's changes in the full context of your published docs. Below the **Preview** button is a URL for your site preview — click it to open the preview in a new tab, complete with the preview toolbar for jumping back into GitBook to view, edit, or comment.

{% hint style="info" %}
You can only preview change requests for sections added to a [published docs site](../../publishing/README.md).
{% endhint %}

{% hint style="warning" %}
If your content is published using share links or authenticated access, the preview function won't appear.
{% endhint %}
